## 目标
参考同级目录 `llama.cpp/.github/workflows/release.yml` 中的 `ubuntu-24-sycl` 作业（行 567–856），为 `stable-diffusion.cpp/.github/workflows/build.yml` 添加一个 SYCL 后端发布作业，并把它接入现有的 `release` 发布作业。

## 范围
**仅 Ubuntu 24.04**（推荐）。理由：
- llama.cpp 的 `release.yml` 只发布 Linux SYCL 包，没有 Windows SYCL 发布作业。
- Windows SYCL 构建依赖 llama 专属的 `examples/sycl/win-build-sycl.bat`，stable-diffusion.cpp 不存在该脚本，需另行编写，工作量与风险显著增加。

## 关键适配点（已通过调研确认）
- **可执行文件名**是 `sd-cli` / `sd-server`（不是 `llama-*`）。`sd-cli --version`（examples/cli/main.cpp:629）只打印版本号后早退，不自动初始化后端。
- **ggml 子模块** 是 `leejet/ggml` fork，其 SYCL 后端 CMake 与 llama.cpp 完全一致：`find_package(MKL REQUIRED)` + `MKL::MKL_SYCL::BLAS`、可选 `find_package(DNNL)`、Level Zero loader、`GGML_SYCL`/`GGML_SYCL_F16` 选项。因此 llama.cpp 的库打包逻辑（ldd 扫描、间接依赖、RPATH、校验）可完整复用。
- **CMake 入口**用 `-DSD_SYCL=ON`（stable-diffusion 原生选项，内部 `set(GGML_SYCL ON)` 传播到子模块），与现有 ROCm 作业用 `-DSD_HIPBLAS=ON` 的模式一致；`-DGGML_SYCL_F16=ON` 直接传 ggml 级选项（Vulkan 作业也是直接传 `-DGGML_VULKAN=ON`，已验证可行）。
- **制品命名**遵循本仓库既有约定：`sd-${tag}-bin-sycl-${OS_TYPE}-${OS_NAME}-${OS_VERSION}-${CPU_ARCH}.tar.xz`（参考 Vulkan 作业），用 `.tar.xz`（不是 llama 的 `.tar.gz`）。
- **后端 .so 位置**：与 CUDA 作业一样，构建后需先把散落在 build 下的 `libggml*.so*` 收拢到 `build/bin/`，再做 ldd 打包扫描。
- **版本约束**：`ccache-action` 用本文件已有的 `v1.2.16`（保持文件内一致），`upload-artifact` 用 `v4`，`actions/checkout@v6`。

## 具体改动（仅修改一个文件：`.github/workflows/build.yml`）

### 1. 新增作业 `ubuntu-latest-cmake-sycl`
插入位置：在 `ubuntu-latest-cmake-vulkan` 作业之后、`windows-latest-cmake` 作业之前。`runs-on: ubuntu-24.04`，`needs: resolve-upstream`。步骤：

1. **Clone** — 与其他作业一致（checkout `leejet/stable-diffusion.cpp`，submodules + fetch-depth 0 + 上游 tag）。
2. **ccache** — `ggml-org/ccache-action@v1.2.16`，key `ubuntu-sycl`。
3. **Dependencies (Ubuntu + Level Zero SDK)** — 安装 `build-essential cmake ninja-build patchelf ocl-icd-opencl-dev wget ca-certificates gnupg`；从 oneapi-src GitHub release 下载安装 Level Zero `.deb` 对（`level-zero` + `level-zero-devel`，v1.28.2+u24.04）。
4. **Setup Intel oneAPI** — 添加 Intel apt 仓库（GPG key + sources.list），安装 `intel-oneapi-compiler-dpcpp-cpp` + `intel-oneapi-mkl-devel` + `intel-oneapi-dnnl-devel`（与 llama.cpp 完全相同；MKL devel 是必需的，`find_package(MKL REQUIRED)` 才能通过）。
5. **Build** — `source /opt/intel/oneapi/setvars.sh --force` 后 cmake：
   ```
   -DSD_SYCL=ON
   -DGGML_SYCL_F16=ON
   -DCMAKE_C_COMPILER=icx -DCMAKE_CXX_COMPILER=icpx
   -DGGML_NATIVE=OFF -DGGML_AVX2=ON -DGGML_FMA=ON -DGGML_F16C=ON
   -DSD_BUILD_SHARED_LIBS=ON -DCMAKE_BUILD_TYPE=Release
   ```
   （CPU 指令集固定为 AVX2+FMA+F16C，保证在不支持 AVX-512 的 Intel GPU 主机上也能运行，与 Vulkan/CUDA 作业的可移植性策略一致。）不含 llama 专属的 `-DGGML_BACKEND_DL -DLLAMA_BUILD_BORINGSSL` 等。
6. **Gather ggml shared libraries** — `find build -name 'libggml*.so*' ! -path 'build/bin/*' -exec cp -av {} build/bin/ \;`（复用 CUDA 作业的做法，保证后端 .so 进入打包目录）。
7. **Bundle SYCL runtime libraries** — 复用 llama.cpp 的 ldd 自动发现逻辑：扫描 `build/bin/*` 所有 ELF 的 oneAPI 依赖，连同 soname 家族一起复制；再显式复制 ldd 看不到的间接依赖 `libur_adapter_*.so`、`libumf.so*`、`libtbb.so*`、`libtbbbind*.so*`；删除 debug 变体。
8. **Set RPATH for portable distribution** — 对 `build/bin/*` 每个 ELF 用 `patchelf --set-rpath '$ORIGIN'`（level-zero adapter 的 `$ORIGIN/../lib` 必须改写，否则设备枚举会静默失败）。
9. **Validate SYCL package contents** — 校验必需库（`libggml-sycl.so`、`libggml.so`）与三个间接依赖；smoke test 用 `sd-cli`（找不到则 `sd-server`）的 `--version`，沿用 llama.cpp 的防御做法（临时移走 `libggml-sycl.so` 再跑 smoke test，然后还原），最后对每个 ELF 做 RPATH + ldd 链接检查（豁免由宿主驱动提供的 `libze_loader`/`libOpenCL`）。
10. **Fetch system info** + **Pack artifacts** + **Upload artifacts** — 套用 Vulkan 作业的 system-info 步骤；打包命名 `sd-${tag}-bin-sycl-${OS_TYPE}-${OS_NAME}-${OS_VERSION}-${CPU_ARCH}.tar.xz`；pack/upload 步骤加与现有作业相同的 `if: ${{ github.event_name == 'schedule' || github.event.inputs.create_release == 'true' }}` 门控（PR 上只跑构建、不打包）。

### 2. 接入 `release` 作业
在 `release` 作业的 `needs:` 列表中加入 `ubuntu-latest-cmake-sycl`，使发布等待该作业完成后再汇总上传。

## 不改动的内容

- 不修改 `resolve-upstream`、`release` 作业的逻辑、其他现有作业。
- 不触碰 README 或任何源码（本仓库只跟踪 workflow）。
